## 1 概述

使用 FPGA 开发板从 TF 卡（Micro SD）中扫描并读取 BMP 格式图片（默认分辨率 640×480），将图像数据写入 SDRAM 帧缓存，并通过 **HDMI 1.4b** 接口在显示器上显示。本例程在《设计参考例程 6》基础上扩展：**支持最多四张 BMP 自动扫描与双缓冲切换**；**支持按键手动切换下一张**；**支持按键开启/关闭自动轮播**；**同步输出 HDMI 音频测试音**（由连接在 **HDMI_B** 接口的显示设备播放）。

（HDMI 在启动时可能会因为同步而显示一段时间黑屏；首图加载完成前画面保持黑屏。）

## 2 功能与原理

### 2.1 HDMI 原理

HDMI 是新一代的多媒体接口标准，英文全称是 High-Definition Multimedia Interface，即高清多媒体接口。它能够同时传输视频和音频，简化了设备的接口和连线；同时提供了更高的数据传输带宽，可以传输无压缩的数字音频及高分辨率视频信号，物理接口如图 2 所示。

如图 3 所示，HDMI 电缆和连接器带有四个差分对，构成 TMDS 数据和时钟通道。这些信道用于传送视频、音频和辅助数据。此外，HDMI 带有一个 VESA DDC 通道，可以访问到接收端的 EDID ROM。可选的 CEC 协议在用户环境中的各种视听产品之间提供高级控制功能。HPD（Hot Plug Detect）热拔插检测信号线。具体接口定义如表 1 所示。

HDMI 接口协议在物理层使用 TMDS 标准传输音视频数据。TMDS（Transition Minimized Differential Signaling，最小化传输差分信号）是美国 Silicon Image 公司开发的一项高速数据传输技术，在 HDMI 视频接口中使用差分信号传输高速串行数据。TMDS 差分传输技术使用两个引脚来传输一路信号，利用这两个引脚间的电压差的正负极性和大小来决定传输数据的数值（0 或 1）。图 4 为 TMDS 编码框图，分别对 8 bit 的 R、G、B 数据编码，输出串行的差分信号。行场同步信号 HSYNC、VSYNC 作为 B 通道的控制信号也进行编码。

### 2.2 SD 卡读取 BMP

本例程中提供了通过 SPI 读取 SD 卡内容的驱动，以及读取 BMP 文件的应用模块，这里简单介绍 BMP 文件的结构。SD 卡具有多种文件系统，例程使用 FAT32 的格式化形式进行读取。

BMP 文件由文件头、信息头、调色板、图像数据四部分组成，调色板可能没有信息。文件头长度为 14 bytes，用于标注 BMP 文件在存储系统中的位置以及文件大小。信息头长度一般为 40 bytes，信息头长度在信息头起始位置（0EH）处用 4 bytes 进行描述；其余内容为图像宽度、高度、色彩平面数量、像素位宽、压缩方式、图片大小、分辨率等信息。一般情况下，头文件合计 54 bytes，之后是图像数据。如果想使用自定义的 BMP 图片，可以使用 notepad++（HEX viewer 插件）等工具检查文件的地址和数据等是否正确。

**本例程相对设计参考例程 6 的增量说明：**

- TF 卡中的图片须为 **640×480、24-bit RGB、非压缩** BMP；不可将 PNG/JPG 直接改后缀为 `.bmp`。
- 上电后 `sd_card_bmp` 模块在 FAT32 卷内 **自动扫描最多 4 张** 合法 BMP，并记录各文件起始扇区。
- 采用 **SDRAM 双缓冲**（`BUF0` / `BUF1`）：写缓冲与显示缓冲分离，切换图片时不中断当前显示。
- 按键 **key1** 触发加载下一张；按键 **key2** 开启/关闭 **1 Hz 自动轮播**（在已扫描到的图片间循环）。
- 数码管显示 SD 卡状态码，便于调试（含义与例程 6 类似）。

### 2.3 系统架构与时钟结构

图 5 系统架构图

系统架构如图 5 所示。其中 50 MHz 为板卡输入时钟 `clk`；**sys_pll** 产生 SD 卡侧 100 MHz（`sd_card_clk`）与 SDRAM 侧 125 MHz（`ext_mem_clk`）及 180° 相移时钟 `ext_mem_clk_sft`；**video_pll** 产生 640×480 像素时钟 25 MHz（`video_clk`）与 5 倍串行时钟（`hdmi_5x_clk`）；**PLL_HDMI_AUDIO** 产生音频主时钟 12.288 MHz（`audio_mclk`）。

数据通路：TF 卡 → SPI 读 BMP → 写 FIFO → SDRAM 帧缓存 → 读 FIFO → `video_timing_data` / `video_delay` → RGB → `video_rgb_to_axis_640x480` → **hdmi_1_4b_transmitter_core_wrapper** → TMDS 编码 → **hdmi_phy_wrapper** → HDMI 差分输出。音频通路：测试音 **hdmi_audio_tone_i2s_64fs** → **I2S_receiver** → **audio_arc_calculate**（ACR 包）→ 与视频一并送入 HDMI 1.4b 发射核。

图像数据在不同时钟域中需通过 FIFO 进行跨时钟域传输。上电后 `startup_pulse` 在 `video_clk` 域产生一拍，触发 HDMI 核读取 **EDID**（DDC/I2C）。

### 2.4 HDMI 1.4b 音频输出原理

HDMI 是新一代的多媒体接口标准，它能够同时传输视频和音频，简化系统连线与接口资源；在本工程中，FPGA 在输出 640×480@60Hz 视频的同时，同步嵌入 **48 kHz** 立体声音频流。

如图 6 所示，本例程音频通路为：`PLL_HDMI_AUDIO` 产生音频主时钟 `audio_mclk`，`hdmi_audio_tone_i2s_64fs` 在 FPGA 内部生成 I2S（Inter-IC Sound）测试音；`I2S_receiver` 将 I2S 串行数据解串为左右声道 24-bit PCM（Pulse Code Modulation）音频样本，并输出样本有效信号 `audio_valid`；`audio_arc_calculate` 计算 ACR（Audio Clock Regeneration，音频时钟重建）包所需的 CTS/N 参数。随后，音频样本与 ACR 参数一起送入 **APUG092 HDMI 1.4b Transmitter** IP（`hdmi_1_4b_transmitter_core_wrapper`），由 IP 核在视频消隐期间通过数据岛包（Data Island Packets）完成音频组包，与视频数据复用后进行 TMDS 编码输出。

接收端（显示器/电视）利用 TMDS 时钟与 ACR 参数恢复音频采样时钟，从而稳定解出 48 kHz 音频并进行播放。本工程使用 48 kHz 常用 N 值（N=6144），CTS 由 `audio_arc_calculate` 动态计算以匹配当前 TMDS 时钟。

图 6 HDMI 1.4b 音频输出原理框图（此处插图）

**HDMI 物理连接：** 本工程 HDMI 差分信号与 DDC 引脚绑定至开发板 **HDMI_B** 接口；视频与音频均从该口输出，请使用自带扬声器或音频输出接口的显示器，并确保未静音。

### 3.4 FIFO 控制器模块

`frame_read_write` 模块中包含一个读 FIFO 和一个写 FIFO，以及对应的控制逻辑。主要接口包含读器件接口、写器件接口、SDRAM 接口等。一次读/写事务在完成握手后需在读/写事务长度完成后结束；或者发起一次新的请求，会将上一次事务终止并清空 FIFO。每次读/写事务包含多次传输，每次传输通过突发传输来进行。此外虽然读和写事务可以同时进行，但由于板卡 SDRAM 读写互斥（参考 SDRAM IP 手册），故读事务和写事务突发同时只会进行一个，且写事务优先于读事务。本例程使用 **双缓冲地址** `read_addr_0/1` 与 `write_addr_0/1`，由 `disp_buf_idx` / `write_buf_idx` 选择当前显示与写入区域。如果需要修改分辨率（图像大小），那么 `read_len` 和 `write_len` 也需注意修改。

## 4 实验步骤

### 4.1 连接

将开发板与上位机通过下载线相连；**HDMI 线接开发板 HDMI_B 接口**再连接显示器（视频与音频均经此口输出）。使用 **FAT32** 格式化 TF 卡，将符合要求的 **640×480、24-bit RGB 非压缩** BMP 文件放入卡中（工程示例图片见 `doc/TF卡图片`，可复制使用），插入开发板 TF 卡槽。建议卡内仅保留需要播放的 BMP，并按期望显示顺序复制。

- **格式化脚本**：`tf_format.bat`（该脚本会自动处理未删除干净的 SD 卡扇区，直接双击运行即可，运行前需确保 TF 卡已插入电脑）

### 4.2 实验操作

1. 使用 Anlogic TD 打开 `src/td_project/HDMI1.4b_Transmitter_v1.0.al`，综合布局布线并下载 bit 流。
2. 程序下载完成后，数码管应显示 SD 卡状态（未插卡或异常时可能为 `0`；正常初始化后多为 `1`）。
3. 上电后系统自动扫描 TF 卡内 BMP；**首图加载完成**后 HDMI 显示第一张图片，同时可听到测试音（需显示器支持 HDMI 音频并打开音量）。
4. 按下 **key1**：手动加载并切换到下一张已扫描到的 BMP（双缓冲切换，切换过程中显示不中断）。
5. 按下 **key2**：开启或关闭 **自动轮播**（约每秒切换一张，在已扫描到的图片间循环）。
6. 若画面全黑：检查 TF 卡是否插入、BMP 格式是否为 640×480 RGB24 非压缩、HDMI 是否接在 **HDMI_B**。
7. 若有画面无声音：检查显示器 HDMI 音频设置、音量及是否使用带扬声器的显示设备。

**最简复现：** 复制 `doc/TF卡图片` 至 FAT32 TF 卡 → HDMI 接 **HDMI_B** → 打开上述 `.al` 工程下载 → 即可看到图片轮播与 HDMI 音频测试音。
