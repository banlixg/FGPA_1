# 淡入淡出扩展接入契约

## 1. 分工边界

本目录只新增独立效果模块。保持原有资源发现、图片解析、内存地址、读取器、音频和TD顶层不变，由接续队友在自己的整机分支中接入。本扩展分支不合并或覆盖队友正在跑的main/工作目录。

推荐实例化`rtl/team_fade_effect.v`，同时加入另两个生产.v。它们是Verilog2001，不依赖厂商原语或加密IP。接口是内部逻辑信号，不要把所有控制口误当成开发板外部引脚。

## 2. 视频信号

```text
显示读取/原有对齐 → team_fade_effect → RGB_to_AXIS → HDMI IP
```

| 封装端口 | 整机连接 |
|---|---|
| clk | 真实video_clk；模块不产生新时钟 |
| rst_n | 该域低有效复位，安全释放；监督器与后端一起清理旧事务 |
| in_rgb[23:0] | 已与输入DE对齐的RGB888，R[23:16]、G[15:8]、B[7:0] |
| in_hs / in_vs / in_de | 同一像素位置的同步/有效信号，不改变原极性 |
| in_x / in_y | 可选16位坐标；尚无坐标时都接0，out坐标可不使用 |
| out_rgb / out_hs / out_vs / out_de | 后续全部使用这一组输出，不能混用原始未延迟信号 |
| out_x / out_y | 对齐后的坐标，供后级OSD/标记使用 |
| frame_tick | 每帧一次、一个时钟宽的安全消隐期事件，不是VS整个电平 |

帧事件必须在有效像素开始前产生，建议留至少两拍消隐裕量。它控制亮度更新，**不等同于内存读调度器的安全换帧条件**。实际换帧仍由后端在自己的安全时机进行。

### 固定流水时序

像素与元数据均经过两级寄存器，不存在AXIS式背压。更明确地说：在第N个上升沿采样输入，该组输出在第N+1个上升沿之后可用。后续同步延迟按这个采样表核对，不凭“几拍”的口头描述猜测。

```text
上升沿N：输入rgb/hs/vs/de/x/y及gain进入第一级
上升沿N+1：对应处理结果及元数据进入输出寄存器
```

本模块不改变像素时钟和帧结构，输入连续就连续输出；DE=0期间RGB输出0。原系统若需处理HDMI/AXIS端的ready，仍由其视频适配层保证连续时序。

## 3. 发起效果

以下所有控制信号都在`clk`域：

| 端口 | 契约 |
|---|---|
| request_valid / request_ready | 同为1的上升沿接受一个任务；未接受时保持请求字段 |
| request_slot[1:0] | 目标帧区0～3 |
| request_slot_valid | 该目标已完整驻留且不会被覆盖；由上层有效帧表确认 |
| effect_enable | 1启用淡化；0委托后端原子硬切，仍保留固定像素延迟 |
| request_step[8:0] | 每帧增减的亮度；0按8处理，257～511钳位到256 |
| abort_transition | 监督器一拍中止；正常自动轮播停止按钮不应中断正在进行的效果 |

配置、目标在接受任务时锁存，任务中修改外部配置只影响后续任务。没有内部无限队列：busy时ready=0，发送方可以保持一个下一任务直到ready，也可以自行合并按键事件；不可丢失valid已提出但尚未接受的请求。

亮度范围0～256，256精确还原8位颜色，0纯黑；颜色运算为`floor((channel*gain+128)/256)`。每个通道为线性数值缩放，不进行伽马校正，不宣称两图交叉混合。

| step | 单段帧数ceil(256/step) | 60fps时单段时间 |
|---:|---:|---:|
| 1 | 256 | 约4.27秒 |
| 4 | 64 | 约1.07秒 |
| 8 | 32 | 约0.53秒 |
| 16 | 16 | 约0.27秒 |
| 32 | 8 | 约0.13秒 |
| 256 | 1 | 约0.017秒 |

实际总时间还包括黑帧保持和后端换帧等待。输入实际帧率不同时时长相应变化。

## 4. 最重要的后端连接

启用效果时，控制器执行：FADE_OUT→完整BLACK_HOLD→ISSUE→WAIT_REPLY→FADE_IN。亮度到0后至少保持一个完整输入帧，才提出switch_valid，确保像素流水线内没有旧的非黑像素。

| 端口 | 契约 |
|---|---|
| switch_valid / switch_ready | 后端接受真正切图任务的握手；暂停时valid/slot/token保持 |
| switch_slot[1:0] | 请求的目标帧编号 |
| switch_token[31:0] | 逐任务递增编号；后端随任务保存并原样返回 |
| switch_cancel | 故障时一拍取消；对应该token，可能取消尚未接受或已经接受的任务 |
| reply_valid | 一个时钟宽的后端完成事件；只能针对已接受任务，允许接受当拍回复 |
| reply_token / reply_slot | 原样的请求编号和目标帧编号 |
| reply_error | 1表示本次切图无法正常完成 |

后端可以把`switch_*`接到现有帧切换控制器的适配层，但**reply_valid成功的前提必须同时满足**：

1. 已在合法的读帧边界采纳目标帧编号。
2. 旧帧读FIFO数据已经清理、排空或通过身份区分，不能混入新帧。
3. 目标帧首行/首像素已经预取到位，后续显示可以从完整新帧开始。

这与“请求已排队”“内存编号改变”“team_frame_commit_bridge.select_done”有不同含义。原桥只能证明采纳编号，队友应结合自己的scanout/frame_ready事件构成完成确认。仅在新图加载成功时回复也不正确，因为加载器不负责实际显示读出。

本扩展收到正确确认后，仍等下一个frame_tick开始淡入。32位token不匹配的回复被忽略，匹配token但slot错误会报故障。后端必须保证不会在编号绕回时还保留旧回复；共同复位必须排空旧事务，不能依赖token来消除复位前所有迟到事件。

### 跨时钟域

若播放控制器/读存储调度器在别的时钟域，新增适配层必须通过稳定多位负载+请求/回应握手传递slot、token、error及完成事件。不能对一个窄脉冲或一组多位总线直接接线，也不能只对每一位各做两级寄存器就声称整体一致。

已有`team_frame_commit_bridge`的源端与此模块可能处于不同域，不能直接无视域差异连接。生产模块保持video_clk单域，是为了让效果独立于队友的存储实现。

## 5. 完成、错误与恢复

| 端口 | 含义 |
|---|---|
| busy | 正在过渡或处于故障等待恢复；为1时不接受新任务 |
| done | 一拍任务结束/恢复到全亮；必须连同error_code判断成功 |
| failed | 一拍错误通知，不保证同时done；有效帧不可用的请求会当拍failed和done |
| fault | 进入安全故障等待状态，亮度0、ready=0 |
| gain / blackout | 当前输入端亮度状态；不是独立的“屏幕已全黑”证明 |
| result_slot | 正常任务目标，恢复后为监督器确认的实际帧 |
| phase | 0空闲、1淡出、2黑帧保持、3提出请求、4等确认、5淡入、6故障 |

`WATCHDOG_CYCLES`默认50,400,000。在25.2MHz视频时钟下约2秒，是**没有阶段进展的超时**；每次有效帧推进会复位计数，因此step=1的长动画不会误超时。实际时钟不是25.2MHz时按真实频率设置，例如`2*VIDEO_CLOCK_HZ`。参数为有符号integer，合法范围1～2,147,483,647。

| error_code | 含义 |
|---:|---|
| 0 | 成功 |
| 1 | 请求目标帧无效，保留原画面、不提出实际切图 |
| 2 | 淡化/黑帧保持/确认后等待期间缺少帧推进 |
| 3 | 后端不接受请求或迟迟不确认 |
| 4 | 相同token回复了错误帧编号 |
| 5 | 后端切图失败 |
| 6 | 外部中止 |
| 7 | 非法状态 |

错误后仍输出连续同步和黑色像素，同时failed/fault报告给监督器。**这是显式故障状态，不能把持续黑屏当成正常扩展效果演示。**监督器应显示/记录错误，并恢复或共同复位。

恢复端口：`recover_valid / recover_ready / recover_slot`。监督器只有确认旧任务已取消并排空、某个实际帧的像素已连贯可读后才能发送。模块锁存该帧编号，在下一帧边界淡入恢复；保留原错误码，不会因恢复而伪报本次切图成功。迟到的正常回复不会自行解除FAULT。

初次整机联调可以把abort_transition和recover_valid接0，由共同复位恢复错误，但仍应连接或观察failed/fault/error_code。自动错误恢复必须等监督器真正具备上述保证后再启用，禁止把recover_valid绑1。

## 6. 接入验收清单

- 仿真30项通过，源/TB摘要匹配；原交接包校验仍通过。
- 实际顶层加入3个.v，RGB/HS/VS/DE都取效果输出；坐标有需要时也取对齐后输出。
- 按键和轮播统一请求效果模块，只有switch握手触发实际换帧。
- 后端确认有FIFO/首行就绪证据；故意延迟确认时始终黑色，不提前露出旧图。
- 连续按键、轮播停止/开启、效果开关、参数更新、复位和错误恢复行为确定。
- 新TD综合与实际视频时钟下的时序通过；小乘法器如何映射LUT/器件资源以报告为准，本包尚无器件资源数字。
- 持板者记录至少4张真实图片、手动与自动切换、多种step、连续运行的视频和异常现象。显示器信号连续，过渡结束全亮、无残留/撕裂/黑屏卡死。
- 基础音视频及其自主架构要求仍需独立完成，淡化效果不替代这些任务。
