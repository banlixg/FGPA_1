# team_bmp_parser 接口 v1

状态：RTL 编译及独立仿真通过；尚未综合和接板。

## 时钟和参数

所有端口均属于同一个 `clk` 域。`rst_n` 低有效，复位会取消当前文件和待输出像素。调用方负责在真实系统中安全释放此时钟域的复位。本模块不产生新时钟。

`IMAGE_WIDTH=640`、`IMAGE_HEIGHT=480` 是默认目标尺寸；本轮小尺寸参数仅用于验证行填充等边界。坐标为 16 位；参数应为正且不超过坐标范围。尚未对超大参数做器件资源评估。

## 文件输入

| 信号 | 位宽 | 约定 |
|---|---|---|
| start_ready | 1 | 为 1 时允许开始一个新文件 |
| start | 1 | 与 start_ready 同时为 1 的上升沿发起一次解析 |
| file_size | 32 | start 被接受时锁存，应来自真实目录项的文件长度 |
| busy | 1 | 一个文件正在解析或等待末像素被接收 |
| file_byte | 8 | 从文件偏移 0 起的连续字节流 |
| file_valid | 1 | 输入字节有效 |
| file_ready | 1 | 解析器允许接收；仅 valid 与 ready 同为 1 时消费 |
| file_last | 1 | 与真实文件最后一个字节一起保持有效，并随该字节握手 |
| abort_file | 1 | 文件读取失败/超时等情况的取消请求；busy 时有效 |

输入 valid 为 1 而 ready 为 0 时，发送端必须保持 byte、valid 和 last。没有字节到来不会自动报错；存储读取超时由文件层判断后通过 abort_file 取消。

模块可能在图片像素区域读完后完成，不继续消费尾部附加元数据。文件层收到 image_done/image_error 后必须关闭或取消本次文件请求，并停止递送剩余字节，之后才可发起新文件。

## 像素输出

| 信号 | 位宽 | 约定 |
|---|---|---|
| pixel_rgb | 24 | R[23:16]、G[15:8]、B[7:0] |
| pixel_x / pixel_y | 各16 | 坐标原点为图片左上角 |
| pixel_valid / pixel_ready | 各1 | 同时为 1 时接收一个像素 |
| image_done | 1 | 一拍脉冲，完整像素区域（含行填充）已接收，最后像素也已被后级接受 |
| image_error | 1 | 一拍脉冲，当前文件失败，后级应使目标帧区保持无效 |
| error_code | 4 | 保持到下一次 start 或复位 |

输出暂停时 rgb/x/y/valid 保持，取消、复位或错误终止时可撤销当前像素。模块仍可能在像素有效时消费行尾填充，图像成功通知必须等待待输出像素被接收。

正高度 BMP 从底行开始输出，但 pixel_y 已转换为左上角坐标。负高度 BMP 从顶行开始输出。后级写入地址按坐标计算，不能既使用 pixel_y 翻转又额外执行一次垂直翻转。

**image_done 不是 SDRAM 写入完成。** 后级写 FIFO 中可能还有数据；帧区 slot_valid 必须等到完整写入完成并且没有错误后才置位。

## 错误码

| 值 | 含义 |
|---|---|
| 1 | 上游传输取消 |
| 2 | 文件尺寸小于最小头，或文件字节流提前结束 |
| 3 | 不是 BM 标志 |
| 4 | 不支持的 DIB 头，或像素偏移覆盖头部 |
| 5 | 宽高不符合配置 |
| 6 | planes 不是 1 或位深不是 24 |
| 7 | 压缩方式不是 BI_RGB（0） |
| 8 | 像素范围、BMP 声明长度、目录文件长度之间不一致或越界 |

头部字段按小端解释。长度边界比较使用加宽结果，避免大像素偏移加法回绕后被误判为合法。
