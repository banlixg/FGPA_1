# FAT32 只读模块接口 v1

日期：2026-10-24。生产 RTL 已实现；卡镜像模型回归通过，尚未连接真实 TF 卡。

## 本轮结构

```text
team_fat32_mount   挂载卷，输出几何参数
       ↓
team_fat32_catalog 枚举根目录，输出 BMP 文件候选描述符
       ↓
team_fat32_file_reader 沿簇链读文件，输出文件字节流
       ↓
team_bmp_parser    识别真正合格的 BMP，输出像素和坐标
```

这些是本项目独立实现的 RTL，没有将原例程的物理扇区 BM 搜索模块改名接入。文件候选与合格图片是两个不同状态：扩展名为 BMP 的目录项不证明其内容正确；还要由 BMP 解析器验证。

## 共同扇区接口

所有接口在同一个 clk 域内；start 只在对应模块 busy=0 时使用，一次一个时钟。输入几何参数在整个操作期间保持稳定。跨到实际 SD/存储时钟的 FIFO 或握手由后续适配层负责。

| 端口 | 方向/位宽 | 含义 |
|---|---|---|
| rd_req_valid / rd_req_ready | 请求方输出/接收方输出，各1位 | 同时为1时接受一次读扇区请求 |
| rd_req_lba | 请求方输出32位 | 卡起点为0的512字节逻辑扇区号 |
| rd_valid / rd_ready | 下层输出/上层输出，各1位 | 每次握手传送一个字节，按0..511顺序 |
| rd_data | 下层输出8位 | 当前字节 |
| rd_last | 下层输出1位 | 必须且仅随第512个字节握手为1 |
| rd_error | 下层输出1位 | 当前请求失败，可不带有效字节 |
| rd_cancel | 请求方输出1位 | 检测到协议错误或超时后的取消脉冲 |

一次只有一个未完成请求。ready=0时，下层保持data/last/valid，不能继续丢出字节。读满512字节才释放当前事务；错误/取消时，下层应清理、丢弃剩余响应，完成必要的SPI收尾，再重新允许请求。

**原 SPI 核的扇区数据输出没有这一套背压保证，后续必须加512字节缓存适配层，不能直接把本接口接到原核上。** 因此本轮卡镜像模型通过不等于已能读实物卡。

team_sector_guard 校验扇区长度、检测错误，并在对方应推进却没有推进时计数超时。合法的下游背压不算超时。WAIT_LIMIT 的单位是当前 clk 周期，默认1000000；整机接线时需根据实际时钟、卡延迟和适配层行为重新确定，不将测试平台的64周期配置带上板。

## 挂载

team_fat32_mount 先读LBA0，支持：

- LBA0直接是FAT32卷引导扇区；
- MBR中第一个类型为0x0B/0x0C的主分区。

成功时 mounted 保持为1，并给出一次 done。下次 start 会先清除 mounted，错误退出时不发布新几何参数。输出 volume_lba、fat_lba（已考虑活动FAT）、data_lba、sectors_per_fat、sectors_per_cluster、cluster_count、root_cluster。

验证512字节扇区、每簇1/2/4/8/16/32/64/128扇区、1/2份FAT、版本0、簇数量、FAT容量、根簇号和分区长度。加宽计算分区与数据区域边界。仅依靠“FAT32”字符串而不校验几何参数不能挂载。

当前不支持GPT、扩展分区、FAT12/16、exFAT、非512字节扇区、写卡、修复或格式化。所支持的是明确范围的只读子集。

## 根目录候选

team_fat32_catalog 跟随根目录簇链，扫描簇内各扇区。跳过删除项、LFN附属项、卷标、子目录、非BMP扩展名和无效簇/长度的候选项；支持BMP扩展名的大小写。

candidate_valid=1时输出：

- candidate_name[87:0]：11字节短文件名，首字符在[87:80]。长文件名可通过已有的短名别名访问，本轮不解码中文长文件名。
- candidate_cluster[27:0]：起始簇。
- candidate_size[31:0]：目录项中的文件字节长度。

接收方保持 candidate_ready=0 可以暂停；描述符会保持。每次握手计入 candidate_count。默认最多32个候选，到上限设置 limited，并在当前扇区收尾后给出 done。默认根目录最多遍历1024个簇；循环链使用常量存储量的循环检测，另有遍历上限。

不能把32个候选都当作已经合格或已经装入缓存。后续资源管理器需保存候选，逐个打开并验证，至少成功加载四张图片；不能遇到第一张坏图就直接认为枚举失败或全部成功。

## 文件读取与 BMP 接线

team_fat32_file_reader 在start时锁存first_cluster、file_size。从簇内各扇区读数据，簇结束后查询活动FAT中的下一簇；不假设文件连续。

- file_valid / file_ready / file_byte / file_last 接到 team_bmp_parser 的同名接口；last随目录文件的最后一个字节有效。
- file_position 是已经被后级接受的字节数，开始时为0。
- 实际文件末尾不足512字节时只输出文件长度内的数据，余下扇区字节会被内部丢弃。
- close_file 可提前关闭文件，例如BMP像素已读完但文件尾还有附加数据。模块丢弃当前扇区剩余字节，收尾后给出done；不能将该done解释成整份file_size字节都已消费。
- 文件层error应取消BMP解析，目标帧区保持无效。
- **发布slot_valid须同时确认BMP成功、文件读取/收尾无错误、SDRAM完整写入完成。** BMP最后一个像素送出后，读卡收尾或写FIFO仍可能未完成。

文件大小为0时不读扇区，直接done；正常BMP候选已在目录层要求长度至少54。簇号越界、坏簇、提前EOC和循环链都报错，不无期限重复读取。

## 状态码

共同错误1=下层I/O失败，2=扇区协议错误，3=超时。

挂载：4=引导签名错误，5=找不到支持的分区，6=几何/格式参数不受支持或越界。

目录/文件：6=起始参数错误；7=无效簇链，或文件尚未读完就到EOC；8=检测到循环链；9=遍历上限。

## 验证与来源

`tools/run_fat32_regression.py`使用自建稀疏卡镜像，直接驱动生产RTL，并把文件字节和BMP像素与独立期望值对比。完整分辨率场景包含四张640×480图片，其中有团队03.bmp；比较1228800个像素与坐标。模型主动检查请求的扇区是否属于测试镜像，错误地址不会被静默补零掩盖。

格式参考：[Microsoft FAT Specification，Microsoft作者的规范公开副本](https://academy.cba.mit.edu/classes/networking_communications/SD/FAT.pdf)，主要是BPB、FAT和目录结构章节。代码为本项目实现；没有复制规范中的整段文字或使用例程目录扫描源码。
