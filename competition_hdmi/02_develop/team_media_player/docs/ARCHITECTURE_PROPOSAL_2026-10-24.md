## 2. 推荐正式架构

TF卡扇区接口 -> 最小FAT32只读文件系统 -> BMP文件解析 -> 四图驻留帧存储 -> 行预取/显示扫描 -> 像素处理 -> HDMI发送。

统一播放控制器负责资源表、请求队列、轮播间隔、帧边界提交和异常状态。显示端输出实际采纳事件，供图号、OSD及后续音频联动使用。

### 与参考例程的实质区别

| 层次 | 当前参考例程 | 建议正式实现 |
|---|---|---|
| 资源发现 | 在有限物理扇区范围找BMP头；未解析FAT32目录和簇链 | 解析分区/引导参数、FAT和目录，枚举真实存在的BMP文件 |
| 文件读取 | 从起始扇区推算后续位置 | 跟随FAT簇链读取，允许文件分散存放 |
| 图片解析 | 沿用bmp_read中的扫描、解析和加载状态机 | 独立字节流解析器，校验文件头、像素偏移、位深、压缩、尺寸和数据长度 |
| 缓存组织 | 两个缓冲区，切图时重新从TF卡加载 | 四张图片启动时装入四个固定帧区；播放时只切换读基址 |
| 切图控制 | 源结束/写结束后更新缓冲编号 | 资源有效性检查、请求/应答跨域、显示帧边界采纳、返回实际显示编号 |
| 像素处理 | 图片像素送往显示 | 自研流水线，默认原彩24位；提供可测的灰度/亮度处理并对齐坐标与同步信号 |
| 音频 | 内部测试音经过I2S接收链送HDMI | 后续独立设计文件型PCM音频读取、缓冲和图音关联；本轮只预留接口 |

常用技术如FIFO、双缓冲或帧缓存本身不是专有实现；不为追求名词不同牺牲稳定性。实质区别由源码、模块职责、控制流程和测试证据共同证明。改名、改参数、换图片、仅新增字幕或转场，都不能独自证明满足此要求。

## 3. 范围与资源约束

- 保持输入要求：至少4幅640x480、24位无压缩BMP。默认显示通路保留RGB888，不以RGB565替代24位能力。
- 帧存储每像素用32位存24位颜色，另外8位保留。每帧307200个32位字；四帧共1228800字，即4915200字节，约4.69MiB。
- EG4S20集成SDRAM标称2M x 32位，按2^21个字计约8MiB。上述四帧容量可容纳；仍需给控制器保留区、对齐和后续音频做明确地址分配，并验证控制器实际寻址范围。
- 建议四个帧基址（32位字地址）：0、307200、614400、921600。字地址不能误当字节地址。
- 一张图必须在完整写入并通过错误检查后才设置slot_valid。至少4张的能力必须实际验证，不把资源表容量当作已能显示4张。
- 初版装载完成后播放时不再持续从TF卡读取图片；TF卡较慢不应迫使视频停顿。启动时间和播放切换时间分开测量。

## 4. 最小FAT32子集

生产模块先支持：512字节逻辑扇区、标准FAT32、根目录内的24位无压缩BMP。按真实文件系统枚举至少4张合格文件。

需要处理：MBR分区起点与无分区卷的识别；BPB参数；簇到扇区换算；根目录簇链；普通短文件名目录项；长文件名附属项/删除项/卷标/目录的跳过；FAT表项掩码与结束标志；文件大小与EOF；超时、非法簇号和循环链等错误退出。长文件名可先通过其短文件名别名读取，不先做中文名称显示。

不固定假设根目录在某个扇区，不假设文件连续，不扫描已删除文件残留作为有效资源。目录条目和BMP头均需验证；跳过错误尺寸或位深的样本后继续枚举。

## 6. 接口草案

- 文件层：file_open_req、first_cluster、file_size；file_byte[7:0]、file_valid、file_ready、file_eof、file_error。
- 解析层：pixel_rgb[23:0]、pixel_x[9:0]、pixel_y[8:0]、pixel_valid、pixel_ready、image_done、image_error。
- 装载层：slot_id[1:0]、slot_valid[3:0]、slot_loaded事件。image_done不等同于SDRAM写完，slot_valid须等待写入完成。
- 播放层：scene_req、scene_id[1:0]；显示端握手接收后在帧边界更新读基址并返回scene_visible、visible_id。
- 参数：auto_enable、interval_ticks或interval_ms；以专用参数控制轮播，不能修改基础时钟参数来凑时间。
- CDC：以上名字只表示逻辑职责。各自时钟、复位、请求应答、数据稳定期和FIFO规则须在接线前定稿。多位图号不直接逐位跨域同步。
