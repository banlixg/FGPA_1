# 四图驻留帧区与帧边界提交接口 v1

状态：生产RTL已实现；内存使用带完成回应的RAM模型验证。真实SD扇区适配、SDRAM控制器、显示读调度及TD时序尚未接入。此处的“写入完成”由内存适配器兑现，不能接成“写FIFO已收数据”。

## 1. 本轮代码如何连接

`team_image_loader`连接现有的`team_fat32_file_reader`、`team_bmp_parser`及新的`team_frame_store_writer`。外部提供挂载后的卷参数和一个目录候选的首簇、长度，加载器沿簇链读取文件，解析像素并写帧区。目录枚举结果是候选，只有加载成功才可作为一张合格图片。

三个条件全部满足才将目标`slot_valid`置1：

1. BMP解析器确认整张图成功且最后像素已被接收。
2. 文件读取器正常结束，包括必要的当前扇区尾部排空。
3. 恰好`IMAGE_WIDTH × IMAGE_HEIGHT`个像素全部收到成功的内存写入回应。

任何一项失败都保留目标帧区无效。失败前可能已经写入部分数据，这些数据禁止显示；重试会从头覆盖完整帧区。

本版采用启动加载、四图驻留的策略。已经有效的帧区直到共同复位前都不允许重写。播放时只改变选择，不重复从TF卡搬图。热插拔、有效帧替换及动态淘汰不在本版接口范围内。

## 2. 地址与数据格式

地址单位为32位的“字”，不是字节。默认640×480，每个帧区307200字。

| 帧区slot | 起始字地址 | 末字地址 |
|---|---:|---:|
| 0 | 0 | 307199 |
| 1 | 307200 | 614399 |
| 2 | 614400 | 921599 |
| 3 | 921600 | 1228799 |

`address = slot × 307200 + y × 640 + x`，坐标原点为左上角。BMP正高度文件可能先输出底行，写入仍使用解析器提供的坐标，不再次翻转。

`wr_data = {R[7:0], G[7:0], B[7:0], 8'h00}`。四帧占4,915,200字节，约4.69 MiB；实际SDRAM容量映射及保留区需在硬件适配时核对。默认21位字地址可以表示本版逻辑地址范围。

参数限制：宽高必须为正且适合16位坐标，四帧总字数必须不超过`2**ADDR_BITS`；本轮没有支持任意超大参数的容量保护硬件。完整分辨率验证使用默认640×480。

## 3. 加载器接口

`team_image_loader`除后续独立的显示桥外，所有端口均属于同一`clk`域；真实SPI或SDRAM若采用其他时钟，必须由适配器处理跨域。

| 端口 | 约定 |
|---|---|
| load_valid / load_ready | 同为1的上升沿接受一个加载任务；未接受时发送方保持任务描述 |
| load_slot | 0～3；有效帧区会令load_ready为0，不能覆盖 |
| first_cluster / file_size | 目录候选的首簇、字节数，在任务接受沿采样 |
| fat_lba / data_lba / cluster_count / sectors_per_cluster | 来自挂载模块；整个任务期间保持稳定 |
| busy | 任务活动中，包括错误后的底层事务排空 |
| slot_valid[3:0] | 已经完整驻留的帧区，各位仅在成功时置1，复位时清0 |
| load_done / load_failed | 一拍结果；结果产生前文件、解析器和帧写入器均已空闲 |
| result_slot / error_code | 本次任务结果，保持到下一次任务 |

加载器在BMP完成后关闭文件剩余部分；正常提前关闭不等于读完文件尾部附加元数据，但已用BMP头和目录长度验证图片范围。扇区排空中报错仍会导致加载失败。

## 4. 扇区读取与内存写入

扇区接口沿用`FAT32接口.md`的`rd_req_* / rd_* / rd_cancel`。真实SPI不能按上层背压暂停发送时，应先收齐512字节再向此接口提供可暂停的数据流；取消后必须正确结束或清理旧事务。

内存接口：

| 端口 | 约定 |
|---|---|
| wr_valid / wr_ready | 同为1接受一次字写入；暂停时地址与数据保持 |
| wr_addr / wr_data | 字地址与32位像素字 |
| wr_rsp_valid | 一拍回应，一次已接受请求恰好对应一次回应；允许接受请求的同一拍返回 |
| wr_rsp_error | 随回应表示写入失败 |

本版最多一个未完成写入，不要求突发写接口。后续SDRAM适配器可以内部缓存/合并，但成功回应必须意味着该字已经对后续读取可见。真实器件吞吐、仲裁和刷新尚未验证。

源文件失败时，写入器会停止收像素并请求终止上游，但已提出而尚未被接受的写请求仍保持，已接受的请求必须等待回应。这样下一次任务不会误收上一次任务的回应。内存适配器必须最终返回成功或失败；本模块没有可丢弃未完成写入的超时重启路径。

复位会清空帧有效标志及接口状态；外部内存适配器必须一起复位/清理旧回应。旧SDRAM内容即使仍在，也不能作为有效帧显示。

## 5. 错误码

| 值 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | BMP解析失败或被取消 |
| 2 | 文件读取失败，包括图片结束后的扇区排空错误 |
| 3 | 像素坐标越界或顺序异常 |
| 4 | BMP完成时像素数不足 |
| 5 | 内存写入失败 |
| 6 | 没有对应请求的内存回应 |

首像素应位于顶行或底行的第0列，随后每行从左到右，行序连续向下或向上。该检查防止重复/跳过坐标导致“数量相同但帧区有空洞”。

## 6. 帧边界选择桥

`team_frame_commit_bridge`提供独立的`src_clk`与`video_clk`域。源端通过`select_valid / select_ready / select_slot`提出选择；只允许提交已经有效且不会再被写入的帧区。此桥本身不筛选`slot_valid`，上层播放控制器负责检查。

桥使用请求/回应翻转握手：源端锁存编号并保持，视频端通过两级控制同步后锁存编号，只在`frame_boundary`采纳。视频端更新`active_slot / active_valid`并发出`commit_pulse`，随后源端才收到`select_done`。忙时只保留一个在途选择，不会自行覆盖或排队。

`frame_boundary`必须来自显示读调度器，表示旧帧读取已结束、允许选择下一帧的时机，不能随意接未经核对的HDMI VS电平。新`active_slot`在该沿之后生效，读调度器应从后续时钟沿使用新编号发起读取，并正确清理/区分旧帧FIFO数据。帧边界承诺不自动保证显示首像素已经切换。

本桥没有RAM读取或视频时序生成能力。手动按键、轮播周期、下一张有效帧选择、读FIFO和HDMI仍待实现。

两个域必须共同断言复位，再各自安全释放；运行中单独复位某一域不受支持。跨域握手的仿真验证不包含模拟亚稳态。真实TD工程还必须检查控制同步、稳定多位负载路径、复位释放及相关时序约束，不能靠直接屏蔽全部跨时钟路径来代替检查。

## 7. 验证入口

在项目根目录运行`tools/run_frame_regression.py`。测试包括BMP到四帧RAM、最后写入延迟/失败、文件收尾失败、源取消后的写入排空、失败重试、帧区保护，以及不同时钟比下的帧边界提交。

新增集成案例直接使用真实`team_image_loader`，由FAT32分散簇链卡模型读文件，逐个核对内存请求地址、RGB数据及最终驻留帧。挂载/枚举有上一轮独立联测证据；此新增案例直接提供生成卡模型的卷参数和文件描述，不声称已经实现整机启动调度器。
